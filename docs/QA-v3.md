# v3 독립 QA 기록

검수 범위: 탄막 주기·예고와 공격의 일치·아이템 네 종류로의 저장 이행·스토리 쌍별 획득 조건. 독립 QA는 기획/엔진 구현자가 작성한 테스트와 별도로 공개 엔진 인터페이스와 실제 앱 저장 정리 함수를 실행했다.

## 실행 결과

`node --test tests/qa-v3-independent.test.mjs`

**15개 통과, 실패 0개.** 최초 실행에서 이전 단일 아이템 저장의 소모량이 복구되는 결함 하나를 재현했고, 엔진과 앱 담당자의 수정 이후 같은 테스트를 통과했다. 블루이의 엔진 관련 검증은 수정 후 118개 통과로 별도 보고되었다. 프로젝트 전체 테스트의 최종 통과 수와 실제 브라우저 검증은 메인 담당자의 통합 결과를 따른다.

## 발견하여 수정한 결함

### 이전 단일 아이템 저장에서 소비한 도움 별이 돌아옴

- 재현: `engineVersion: 1`, `ability: 'slippers'`, `charges: 0`, `energy`와 `availableCharges`가 없는 정상 구버전 저장을 네 종류 인벤토리로 불러옴.
- 변경 전: 삭제된 능력이므로 기존 소비량 분기를 건너뛰어 도움 별이 3개로 돌아옴. 구두의 기존 최대 2회를 이미 썼다면 1개가 남아야 함.
- 앱 측 원인: 저장 정리에서 삭제된 `ability`를 null로 바꾸면 엔진이 옛 최대 횟수를 추론할 정보도 사라짐.
- 수정: 앱이 정리 전 구버전 이름/횟수로 에너지를 보존한다. 엔진은 버전과 관계없이 유효한 `energy`를 우선 복원하고, 없을 때는 제거된 네 종류까지 포함한 옛 최대 횟수로 소모량을 계산한다. 현재 획득 권한은 여전히 호출자가 완료한 이야기로만 결정한다.
- 회귀: 제거된 네 종류의 모든 유효 잔여 횟수와 실제 앱 정리→엔진 복원의 연결을 확인했다.

## 통합 담당자에게 전달한 화면 검수 항목

1. `telegraphs[].rays[]`의 모든 팔을 렌더링하여 네 갈래 실제 빛줄기와 화면 예고가 맞는지 실제 화면에서 확인한다. 엔진의 각도 일치만으로 화면이 올바르다고 주장하지 않는다.
2. `wheel` 보스가 리본 이모지나 누락 아이콘으로 표시되지 않아야 한다. 토끼 세 귀는 기존 `race-twist`에서 발견된 문제이며 새 그림과 최종 표시 크기의 시각 검수는 메인/에이미 담당이다.
3. 한쪽 이야기만 끝난 시점에는 선물을 주지 않고, 역순으로 쌍을 완성해도 한 번만 보상한다. 다시 완료해도 선물 획득 화면을 반복하지 않는지 실제 완료 흐름을 확인한다.
4. 튜토리얼 외 조작 설명이 없어도 터치 장치에서는 이동/그리기 수단을 사용할 수 있어야 한다. 넓은 보드와 네 아이템이 가로·세로 화면에서 가려지지 않는지 확인한다.
5. 아이템 키는 1~4만 현재 슬롯에 대응하고, 5~8을 눌러 숨겨진 구버전 능력을 사용할 수 없어야 한다.

## 검증의 한계

이 기록은 자동화된 엔진/저장 검증이다. 프레임 간격 두 가지에서 시간과 상태를 검증했으며 실제 기기의 프레임 성능을 측정한 것은 아니다. 브라우저에서의 렌더러, 다운로드한 독립 파일의 실행, 스마트폰 실기기 터치, 음향 청취, 아동과 성인의 난이도 평가는 이 독립 QA에 포함하지 않는다. 새 아트의 납품 상태와 이미지별 수작업 검수도 메인 통합 기록을 따른다.

## 메인 통합 검증 — 2026-09-14

- 전체 `node --test --test-reporter=spec tests/*.test.mjs`: **155개 통과, 실패 0개**. 엔진, 실제 앱 이벤트와 저장 정리, 전체 8장 보상 흐름, 스토리, 휴대 HTML 내보내기, 화면 크기와 교차 예고선 렌더러를 포함한다.
- `npm run build`: 복원 8개 + 이야기 27개 그림 키를 내장한 단일 HTML 생성 성공. 루트 index.html과 output/storybook-dream.html은 동일하다.
- `node scripts/verify-release.mjs`: 35개 JPEG 항목의 데이터와 모든 장면 참조, 외부 URL/외부 코드·스타일 없음, 배포 초기 저장이 빈 상태임을 확인했다.
- 브라우저에서 최종 단일 HTML을 로컬 서버로 실행했다. 토끼 소개 3장을 Enter·Space로 넘기고 Esc 건너뛰기, 지도 이동, 튜토리얼의 바퀴 보스, 후반의 네 아이템을 확인했다.
- 1280×720에서 게임판 1250×535, 390×844에서 가로 넘침 없이 게임판과 네 아이템 표시. 844×390 가로 화면에서도 페이지 크기가 화면을 넘지 않는다. 390의 아이템 이름 겹침을 발견해 세로 배치로 고치고 최종 화면을 재검수했다.
- 전체 화면 버튼을 눌러 브라우저가 2560×1440으로 확장되고 다시 버튼을 누르면 원래 크기로 돌아오는 것을 확인했다. 임시 반응형 크기 설정은 검수 후 해제한다.
- 후반 PC 화면에는 방향 버튼과 튜토리얼 안내가 표시되지 않는다. 터치 입력 연결은 자동 테스트로 검증했고 실제 터치 기기에서의 검증은 미실시다.
- 화면에서 네 갈래 X 빛줄기 예고가 모두 나타나는 것을 직접 확인했다. 예고와 실제 공격의 각도·길이 일치 및 저장 후 유지 여부는 독립 엔진 테스트와 렌더러 테스트로 확인했다.
- 메인이 아트 34종을 직접 검수하고 토끼 귀와 자전거 탑승 자세 등을 수정했다. 자세한 결과는 art-review-v3.md를 따른다.

실제 아이와 어른의 난이도 체감, 스마트폰 파일 앱의 실행, 스피커 청감은 이번 자동/브라우저 검증과 구분한다. 브라우저 검수는 로컬 HTTP에서 했으며 file:// 직접 실행은 여기서 자동 검증하지 않았다. 배포 파일은 외부 모듈을 읽지 않도록 전부 내장했다.
