# 토끼 탐정 v5 — 완성도·재미 향상 로드맵

2026-09-25 작성. 기준: v4.1.0 (커밋 1e14754). 목표는 프로토타입을 **"아이가 스스로 다시 하고 싶어 하는 게임"** 으로 올리는 것이다.
결정 사항: Windows에서만 돌아가면 된다(단일 HTML 제약 해제). 스토리는 A안(전체를 잇는 범인 한 명).

---

## 0. 한 줄 결론

재미를 막는 건 기능 부족이 아니라 **조작감·위협·보상 피드백 세 가지가 모두 밋밋한 것**이다.
순서는 **기반 정리 → 조작감 → 피드백 → 보스/적 재설계 → 스테이지 다양성 → 스토리 A안 → 아트/사운드 → Windows 패키징**.
보스 재설계는 12판을 한꺼번에 하지 않고 **한 판(4번 빨간 모자)을 완성 품질로 먼저 만들어(버티컬 슬라이스) 재미를 확인한 뒤** 나머지로 넓힌다.

## 1. 현재 진단 — 재미를 막는 것들

### 1-1. 조작감 (가장 먼저 느껴지는 문제)

| 문제 | 근거 | 체감 |
|---|---|---|
| 칸 단위 이동 + 느린 시작 속도 | `PLAYER_SPEEDS=[7,…]` 칸/초, 72칸 보드 | 가로지르는 데 10초. 답답함 |
| 보이는 위치와 판정 위치 불일치 | 논리 위치가 먼저 칸을 이동하고 `visualQueue`가 뒤따라감 (engine.js:86) | "안 맞았는데 맞았다" |
| 키를 누르는 순간 한 칸 즉시 이동 | `setDirection(...,{immediate})` (engine.js:64) | 톡 튀는 느낌 |
| 꺾기 입력 버퍼 없음 | 방향은 칸 경계에서만 반영 | 모서리에서 한 칸 지나침 |
| Space를 누른 채 방향키 | 두 손 동시 조작 | 7살에게 가장 큰 진입 장벽 |
| 가변 dt, 고정 타임스텝 없음 | `step(dt)` 에 프레임 간격 그대로 | 프레임 흔들림이 이동 흔들림으로 |

### 1-2. 위협 — 보스와 적

| 문제 | 근거 |
|---|---|
| 보스가 당구공: 일정 속도 직진, 벽에서 반사만 | engine.js:106 |
| 예고(1.6~2.4초) + 공격 + 회복(~2초) 동안 **완전 정지** → 절반 가까이 서 있음 | engine.js:102 |
| 패턴이 고정 순서로 돌기만 함, 플레이어 행동에 반응 없음 | `attackIndex % n` (engine.js:109) |
| 고리 패턴은 90° 틈이 항상 플레이어 방향 → **구조적으로 맞지 않음** | engine.js:114 |
| 12보스가 수치만 다르고 행동은 같음. 빵 바구니와 콩나무 종이 똑같이 움직임 | `BOSS_PROFILES` |
| 졸병 '돌진'은 같은 방향으로 1.7배 빨라질 뿐, 추적하지 않음 | engine.js:98 |
| 보스가 선(플레이어의 약점)에 관심이 없음 → 긴장의 원천이 우연 | — |
| 보스를 가두면 남은 시간은 위협 없는 칠하기 → 판 후반이 지루함 | engine.js:157 |

### 1-3. 보상과 피드백

- 땅 확보가 **즉시 한 번에** 칠해짐. 확보 크기와 무관하게 같은 연출.
- 피격 시 선이 즉시 사라짐. 히트스톱·흔들림·되감기 연출 없음.
- 단서 발견이 토스트 한 줄. 이 게임의 클라이맥스인데 가장 약함.
- 판 평가·수집 요소가 없어 **다시 할 이유**가 없음.
- 선물 4개 중 시계는 12판을 다 깬 뒤에만 생겨 사실상 쓸 일이 없음.

### 1-4. 화면 품질

- 게임판 배경은 6컷 시트의 한 칸(**약 622×393px**)을 전체 화면으로 확대 → 1080p에서 약 3배 확대, 흐림.
- 적·보스·탄은 코드로 그린 원과 도형. 졸병은 점에 '!' 글자.
- 판 대부분이 거의 검정(`rgba(9,15,29,.985)`)이라 시작 화면이 비어 보임.
- 매 프레임 DOM 15곳 갱신, `JSON.stringify` 2회, 버튼마다 `earnedAbilities()` 재계산 (app.js:112-125) → 끊김 요인.
- 예고선 길이를 매 프레임 광선당 400회 샘플링 (render.js:88).

### 1-5. 코드 기반

- 핵심 파일이 압축된 한 줄 코드: engine.js 32KB/228줄, app.js 33KB/163줄. **어떤 개선이든 이 상태에서는 느리고 위험하다.**
- 단일 HTML 제약에서 온 복잡도: 그림 9.6MB base64 임베딩, 진행을 담은 HTML 내보내기(portable.js), 변조 방지 저장 검증(engine.js:180-227), v1~v6 저장 마이그레이션.
- 테스트·문서가 버전별로 누적(테스트 13파일, QA 문서 5개). 테스트 자체는 202/203 통과(1개는 빌드 산출물 누락).

### 1-6. 스토리

12사건이 모두 **"물건이 엉뚱한 곳에 있었다 → 찾았다 → 웃었다"** 동일 구조. 추리가 없고, 보스는 사건과 무관하며, 12개가 왜 동시에 일어났는지 설명이 없다. → A안으로 해결 (6장).

## 2. 플랫폼 결정

Windows 전용이 허용되면서 선택지가 넓어졌다.

| 안 | 장점 | 단점 | 판단 |
|---|---|---|---|
| **웹 기술 유지 + Electron으로 exe 포장** | 그림·스토리·음악·테스트 전부 재사용. 자동 테스트와 브라우저 검증이 쉬움. Node만 있으면 빌드 | exe 용량 큼(~150MB, 가족용이라 무관) | **추천** |
| Godot 4로 재작성 | 트윈·파티클·셰이더·게임패드 기본 제공 | 전면 재작성, 기존 테스트 폐기, 자동 검증 어려움 | 비추천 — 코드 규모(약 150KB)가 작아 웹에서도 같은 품질 가능 |
| 현재 단일 HTML 유지 | 변경 없음 | 9.6MB 임베딩, 포터블 저장 등 복잡도 유지 | 제약만 남음 |

**추천 구성**
- 개발: Vite(즉시 새로고침) + JavaScript 모듈. 엔진 핵심만 JSDoc 타입 주석.
- 렌더링: Canvas 2D 유지로 시작한다. P2(피드백)에서 안개 가장자리 글로우·블러가 성능 한계에 닿으면 그때 PixiJS(WebGL)로 교체를 판단한다.
- 배포: Electron 포터블 exe 하나. 저장은 `%APPDATA%\storybook-dream\save.json`.
- **제거되는 것**: 그림 base64 임베딩, 진행 포함 HTML 내보내기, 변조 방지 검증 대부분, v1~v5 저장 마이그레이션(한 번 변환 후 폐기).
- **추가 가능해지는 것**: 게임패드(아이에게 키보드보다 훨씬 쉬움), 고해상도 그림, 진짜 전체 화면.

## 3. 목표 경험 (완성도 판단 기준)

1. **30초 규칙**: 7살이 설명 없이 30초 안에 "선을 그어서 가두는 게임"임을 안다.
2. **아슬아슬 → 해냈다**: 한 판 3~5분. 판마다 최소 한 번은 "위험했는데 연결했다"는 순간이 생긴다.
3. **보스가 기억에 남는다**: 판이 끝나면 "빵 바구니가 굴러오던 거"처럼 보스의 행동으로 판을 기억한다.
4. **다시 하고 싶다**: 판 평가 별과 숨은 스티커가 재도전 이유를 준다.

측정 가능한 기준:
- 60fps 유지, 입력→화면 반응 1프레임 이내, 보이는 위치 = 판정 위치.
- 첫 시도 클리어율: 1~4판 90%↑, 5~8판 70%↑, 9~12판 50%↑ (하트 3개 기준, 실제 플레이로 조정).
- 판당 보스가 정지해 있는 시간 비율 25% 이하.

## 4. 단계별 로드맵

크기 표시: S(하루 이내) · M(며칠) · L(일주일 안팎). 작업은 Claude와 진행하는 기준이며, 아트 제작 시간은 별도다.

### P0. 기반 정리 — L

동작은 바꾸지 않고, 이후 모든 작업을 빠르고 안전하게 만든다.

- [x] 코드 포맷 풀기 (Prettier). 테스트 통과로 동작 동일 확인.
- [x] 엔진 분할: `src/game/` 아래 `config` / `player` / `enemies` / `boss` / `projectiles` / `save`.
- [x] **고정 타임스텝** (1/120초 단위). 엔진에 난수가 없어 같은 입력 → 같은 결과가 이미 보장된다.
- [x] HUD는 값이 바뀔 때만 DOM 갱신.
- [x] 개발자 오버레이(F3, 개발 모드 전용): FPS, 판정 범위, G 무적, N 보스 공격 강제, W 즉시 해결.
- [x] Vite + Electron 셸. 저장은 앱 저장소(%APPDATA%)의 localStorage, 가족 그림도 유지. 진행 포함 HTML 내보내기는 JSON 백업 하나로 대체.
- [ ] app.js 분할: `screens/`(홈·지도·스토리·게임·설정) / `input` / `hud`. → P1에서 입력·HUD를 고칠 때 함께.
- [ ] 이벤트 버스: 엔진은 사건만 발행하고, 소리·연출·HUD가 구독. → P2 연출 작업과 함께.
- [ ] 테스트 정리: 버전별 파일 → 기능별. → P1·P3에서 규칙이 바뀌는 테스트부터 옮긴다(현재 v4 수치를 고정하는 테스트가 많다).

**완료 기준**: v4.1과 같은 게임이 exe로 실행되고, 테스트가 전부 통과하며, 각 파일이 사람이 읽을 수 있는 형태다.

### P1. 조작감 — M

- [x] **보이는 위치 = 판정 위치**. 토끼가 칸 중심에서 칸 중심으로 미끄러지고(glide), 보이는 위치에서 판정한다. 안전한 땅을 벗어나는 첫 걸음부터 맞을 수 있다.
- [x] 속도 8.5 / 10 / 11.5 / 13칸/초(기존 7 / 8.8 / 10.6 / 12.4), 출발 0.08초 가속. 시작한 한 칸은 항상 끝까지 가서 칸 중심에 멈춘다.
- [x] **꺾기 예약**: 걷는 도중 누른 방향은 다음 칸 중심에서 꺾는다. 짧게 톡 누르면 정확히 한 칸.
- [x] **선 긋기는 Space 유지 방식 그대로** (결정됨). Space를 누르고 뗄 때 짧은 소리, 뗀 뒤의 선은 옅은 점선(되짚기만 가능).
- [x] 게임패드: 십자키·왼쪽 스틱 이동, A = Space(선 긋기·다음 장·선택), B/Start = 쉬기, X·Y·LB·RB = 선물 1~4. *(실제 패드로는 아직 확인하지 않음)*
- [x] 토끼 애니메이션: 좌우 방향 바라보기, 걸음마다 통통 튀기, 선 긋는 동안 앞으로 기울기. (멈춤 숨쉬기는 스프라이트 교체 때)
- [x] 화면 보간: 규칙은 1/120초 단위로 진행하고, 화면은 그 사이를 이어 그려 모니터 주사율과 관계없이 매끄럽다.
- [ ] 판정 관대화: 현재 탄 판정(0.65칸)은 그림 크기와 거의 같다. 플레이테스트 후 조정.

**완료 기준**: 처음 잡은 사람이 "부드럽다"고 느끼고, 모서리를 돌 때 한 칸 지나치는 일이 없다.

### P2. 피드백(손맛) — M

- [x] **땅 확보 연출**: 닫은 선에서 바깥쪽으로 0.35초 동안 안개가 물감처럼 걷힌다. 확보 비율 팝업(+N%), 선을 따라 반짝이, 확보가 클수록 높아지는 효과음.
- [x] **큰 확보(10%↑)**: 화면 흔들림 + 살짝 확대 + "와!" + 전용 효과음.
- [x] **피격**: 0.12초 멈춤(히트스톱) → 흔들림 → 잃은 선이 출발점으로 되감기며 사라짐, 하트 줄이 튀어 오름.
- [x] **적 가두기**: 별 가루로 터지고 전용 효과음, 보스는 "잡았다!".
- [x] **단서 발견 = 클라이맥스**: 0.7초 느린 화면, 단서 쪽으로 확대, "〇〇 발견!" 큰 글씨, 반짝이 폭발, 팡파르.
- [x] 밝힌 땅과 어둠의 경계에 따뜻한 테두리 빛.
- [x] 걸음 별·단서에 퍼지는 빛 고리.
- [x] 이벤트 연결: 엔진 이벤트를 `src/fx.js`(Effects)가 받아 연출·소리를 맡는다. 연출은 실제 시간, 규칙은 연출이 정한 속도(멈춤·느린 화면)로 진행.
- [ ] 미확보 영역에 그림 실루엣 비치기 — 현재 안개 투명도로 희미하게 보이는 수준 유지. 고해상도 배경이 들어오면 재검토.

**완료 기준**: 소리 없이 봐도 "잘했다 / 아팠다 / 찾았다"가 화면만으로 구분된다.

### P3. 보스·적 재설계 — L (핵심)

#### 공통 구조
- **보스 = 상태 머신 + 행동 목록 + 상황별 가중치 선택.**
  - 플레이어가 선을 긋는 중 → 추적·차단 계열 가중치 상승.
  - 플레이어가 안전지대 → 위치 잡기·장판 설치 계열.
  - 같은 행동 연속 금지, 직전 두 행동은 가중치 감소.
- **이동 모드**: 배회 / 선 쪽으로 기울기(회전 속도 제한이 있어 피할 수 있음) / 예상 지점 매복.
- **예고 개선**: 정지 예고 1.6~2.4초 → **몸짓 예고 0.9~1.3초**(웅크림·부풀기·색 변화 + 고유 소리). 일부 공격은 움직이면서 쏜다. 목표: 정지 시간 비율 25% 이하.
- **2단계(복원 50%)**: 표정·색이 바뀌고 대표 기술 강화판이 열림. 보스가 도망치듯 넓은 쪽으로 이동하기 시작.
- **보스 가두기 보상**: 가두면 목표 복원율 −10%p + 남은 졸병 약화. 후반 칠하기 지루함을 없앤다.
- **적응형 난이도**: 같은 판에서 연속 2회 피격 시 탄속 −10%(최대 −20%). 보호자 설정의 쉬움/보통/도전.

#### 새 적 유형
| 유형 | 행동 | 등장 |
|---|---|---|
| 배회 졸병 | 현행 + 부드러운 곡선 이동 | 2판~ |

## 6. 스토리 A안 — 범인 한 명이 12사건을 잇는다

### 범인 초안: 꼬마 까치 **"또롱"**
- 동화책 **맨 마지막 장**에 사는 까치. 반짝이는 물건을 좋아한다.
- 아이는 매일 밤 책을 읽다 먼저 잠들어 **마지막 장까지 간 적이 없다.** 그래서 또롱의 이야기는 한 번도 읽힌 적이 없다.
- 또롱은 다른 동화의 중요한 물건을 가져가면 친구들이 자기를 찾으러 와 줄 거라 생각했다. 나쁜 마음이 아니라 **외로움**.
- 보스는 또롱이 물건 대신 두고 간 **"장난 소품"** 이 제멋대로 움직이는 것. 가두면 또롱의 **깃털**이 남는다.

### 12사건에 심는 연결 고리
| 구간 | 장치 |
|---|---|
| 1~3판 | 해결 컷 구석에 검은 깃털. 토끼: "이상하네, 여기 새가 있었나?" |
| 4~6판 | 목격담 등장("검고 흰 새가 반짝이는 걸 물고 갔어"). 사건 수첩에 **용의자 카드** 생김 |
| 7~9판 | 또롱의 발자국 지도. 물건들이 **책의 뒤쪽**으로 옮겨지고 있다는 추리 |
| 10~12판 | 또롱이 멀리서 지켜보다 도망침. 12판 해결 직후 마지막 장으로 가는 길이 열림 |
| **최종장** (신규) | 또롱의 둥지. 싸움이 아니라 둥지 주변을 밝혀 또롱의 **읽히지 못한 이야기 그림**을 되찾는 판. 보스 없음, 흩날리는 깃털만 피하는 짧은 판 |
| 엔딩 | 아이가 처음으로 마지막 장까지 읽어 준다. 또롱이 물건을 돌려주고 수사 짝꿍으로 합류. 아침, 머리맡에 작은 검은 깃털 |

### 기존 자산 영향
- 12사건의 소개·해결 대사: **대부분 유지**하고 깃털·목격담 한 줄씩 추가.
- 추가 그림: 또롱 캐릭터 시트, 최종장 6컷, 해결 컷 12장에 깃털 디테일(수정 또는 오버레이), 엔딩 1컷 교체.
- 선물 페이지 화자 '책갈피 반짝이'와 이름이 겹치지 않도록 범인 이름은 '또롱'(가칭).
