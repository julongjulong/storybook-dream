## 판당 하트 세 개

1. 각 새 도전은 하트 3개로 시작한다.
2. 안전 지역에 있거나 피격 직후 보호 시간 중이면 하트를 잃지 않는다.
3. 거북이 보호막이 있으면 보호막 한 번만 소모한다. 하트는 그대로다.
4. 보호막 없이 실제로 현재 선이 끊기는 피격을 받으면 하트 하나를 잃는다. 이번 선만 지우고 안전 출발점으로 돌아온다. 이미 밝힌 그림, 찾은 단서, 걸음 별과 아이템 사용 기록은 유지한다.
5. 하트가 남아 있으면 4초간 보호받고 계속한다. 하트가 0이면 이번 도전이 끝나며 이동·탄막·아이템·승리 판정을 멈춘다.
6. 엔진은 자동으로 다시 시작하지 않는다. 앱의 재도전 선택으로 새 판을 만든다. 다른 사건의 완료 기록과 받은 선물은 유지한다.

승리는 여전히 **목표 복원율 + 해당 사건의 단서 발견**이 모두 필요하다. 패배한 상태에서 면적이 충분해져도 승리로 바뀌지 않는다.

## 앱과 엔진 연결

- 공개 상태: lives는 0~3 정수, lost는 패배 여부다.
- 일반 피격: hit 이벤트에 현재 lives와 terminal:false를 담는다.
- 마지막 피격: 먼저 lost=true/lives=0을 설정하고 hit({lives:0,terminal:true}), 이어서 lose({lives:0})를 각각 한 번 알린다. 따라서 앱이 hit 즉시 저장해도 0하트가 정확히 남는다.
- 엔진은 저장 복원 중 이벤트를 발행하지 않는다. 앱은 생성 직후 engine.lost를 확인해 패배 화면을 보여준다.
- 마지막 피격 프레임에도 뒤따르는 적·탄의 이동과 보스 타이머 처리를 중단한다. 이미 패배한 판에서 재차 피해를 처리하거나 lose 이벤트를 반복하지 않는다.

## 저장 호환과 검증

저장 버전은 engineVersion:6, balanceVersion:4.1이다. lives와 lost를 함께 저장한다.

- 정상적인 최신 저장은 남은 하트가 그대로 이어진다.
- 최신 저장의 하트가 0이거나 lost가 true이면 0하트 패배 상태로 복원한다. 단순 새로고침으로 회복되지 않는다.
- v4까지의 버전 5 이하 저장은 새 규칙의 하트 3개로 이전한다. 땅, 단서, 걸음 별, 아이템 사용 횟수와 공용 도움 별은 보존한다. 변경 전 탄막과 공격 예고는 초기화한다.
- 최신 탄막 저장은 빨라진 속도, 남은 수명과 예약 발사 간격을 검증하고 이어간다.
- 기본 영토·경계·플레이어·적 좌표가 잘못된 저장은 원자적으로 거부한다. 손상된 자료를 정상적인 패배 저장으로 간주하지 않는다.

회귀 검증은 3회 피격, 보호막과 무적, 마지막 프레임 정지, 단 한 번의 패배 이벤트, 하트 저장·복원, 이전 버전 이전, 빨라진 탄막과 가장 빠른 보스의 저장 호환을 포함한다.
